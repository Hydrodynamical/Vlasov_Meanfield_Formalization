# Build-path retrospective — data-direct figures for the paper

Generated by [`analyze.py`](analyze.py) over the full git history (362 commits,
2026-05-23 → 2026-06-25). Each figure has a matching CSV. Re-run with
`python3 Vlasov/formalize/retrospective/analyze.py` from the repo root.

All three series are extracted *directly from the build path* — no manual
annotation, no estimation.

## 1. Sorry trajectory — the migrating proof frontier
`sorry_trajectory.csv` / `sorry_trajectory.png`

Per-commit count of **live `sorry`** (comment- and docstring-stripped) in each
production file under `Vlasov/Vlasov/`, stacked so the leaves sum to the total.

- Only **4 files** ever carry live sorries; at any moment essentially **one
  active leaf** holds them. The frontier migrates
  `Basic` → `OT/CharacteristicFlow` → `OT/WeakToLagrangian`, each driven to 0.
- **Peak total = 24**; **HEAD total = 0** (the 0-live-sorry claim, reproduced
  from history rather than asserted).
- The clean gap (~Jun 5–11) is the Phase-D file extraction: the marquee library
  sat at 0 live sorries between the well-posedness arc closing and the bridge
  opening.

## 2. Cumulative named lessons — the discipline framework as meta-knowledge
`lessons_cumulative.csv` / `lessons_cumulative.png`

Distinct named lessons present in `CLAUDE.md` at each of the **36** commits that
touched it, split by series (L = Lean/tooling, P = process, M = math,
B = bridging).

- **4 → 34 lessons** over the build.
- The **four-series taxonomy crystallized in one commit** (`c96d2ff`,
  2026-05-29): the file jumps from L-only (8 lessons) to all four series
  (L9/P2/M1/B1 = 13). Before this, lessons were an undifferentiated L-list.
- **P-series spikes 2026-05-31** (`d57c892`: +4 process lessons in one commit,
  P6→P10) — the Stage-2b/Stage-4 cascade sessions.
- **L-series grows steadily through June** (L11→L16) tracking the
  variational-equation grind; the framework stops growing after the crux closes
  (last lesson L16, 2026-06-15).

## 4. Blueprint dependency graph (paper Figure 1)
`blueprint_depgraph.pdf` / `.png` / `.dot`, extracted by [`depgraph.py`](depgraph.py)

The faithful dependency graph the LeanArchitect/leanblueprint pipeline renders —
edges read directly from the elaborated Lean proof terms. The web output draws it
client-side (d3-graphviz from a DOT string in
`blueprint-demo/blueprint/web/dep_graph_document.html`); `depgraph.py` pulls that
exact DOT out, swaps the transparent background for white, and renders a static
vector PDF (+ PNG preview) with graphviz `dot`. 37 nodes, 57 edges. Box = def /
assumption, ellipse = theorem; dashed edge = statement-level use, solid =
proof-level use; green = formalized (`leanok`). Included in `PAPER.tex` as the
human-auditable cross-check of the OT-layer / kinetic-content separation.

## Method notes (for honesty in the paper)
- "Live sorry" = `\bsorry\b` after stripping Lean line (`--`) and nested block
  (`/- -/`, `/-- -/`) comments. The word "sorry" appears constantly in prose, so
  unstripped grep over-counts badly; HEAD = 0 is the validation that the strip
  is correct.
- Production library = `^Vlasov/Vlasov/.*\.lean$`, excluding the dev scratch
  leaf. Tooling/blueprint Lean files under `formalize/` are excluded.
- Lessons counted by `^### ([LPMB])\d+\.` headers (count *present*, robust to
  renumbering).
- Taxonomy is a subject-line heuristic; the raw conventional-commit prefixes are
  in `commit_prefixes.csv` if a different cut is wanted.
