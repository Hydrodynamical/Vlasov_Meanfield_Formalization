## 1. The formalized result

A Lean 4 / Mathlib formalization of the mean-field derivation of the Vlasov equation along the
**Dobrushin route**, together with the **weak ⟹ Lagrangian superposition principle**. The three
headline theorems are:

| Theorem | Lean declaration | Statement |
|---|---|---|
| Forward well-posedness | `vlasovWellPosedness` | Under `AssW` (`W ∈ C^{1,1}`), a unique forward Lagrangian solution exists for each finite-first-moment datum. |
| Dobrushin stability (1979) | `dobrushin` | `W₁(f_t,g_t) ≤ e^{Ct} W₁(f_0,g_0)` for any two solutions. |
| Superposition principle | `weak_isLagrangianVlasovSolutionOn` | Under `AssW2` (`W ∈ C²`), **every weak (Eulerian) solution is Lagrangian** — it is the pushforward of its datum along the flow it generates. |

The third is the novel contribution: it upgrades uniqueness from "unique *Lagrangian* solution" to
"unique *weak* (PDE) solution", ruling out phantom distributional solutions.

**Trust anchor.** All three are *axiom-clean*: `#print axioms` reports exactly
`[propext, Classical.choice, Quot.sound]` — the three standard Lean/Mathlib axioms, **no `sorryAx`,
no project-specific axioms**. The entire production library is **0 live `sorry`**.

## 3. The build cycle (methodology)

The formalization was produced by a **human-in-the-loop, LLM-agent-assisted** pipeline. One full
cycle, as demonstrated end-to-end this session, has six stages:

1. **Specification.** The target theorem is fixed in LaTeX (`formalize/vlasov.tex`, assumption `ass:W2`,
   theorem `thm:weak-lagrangian`).
2. **Scaffolding (LaTeX → Lean).** A four-stage pipeline (`latex-parser` → `lean-translator` →
   `lean-fixer` → `lean-verifier`, driven by `formalize.sh`) turns the spec into compiling Lean
   *statement skeletons* with `sorry` bodies and a coverage report.
3. **Decomposition + proof.** Oversized obligations are split into named sub-lemmas
   (`sorry-decomposer`); leaves are discharged either by a proof-search agent (`sorry-prover`) or
   by **model-driven interactive development in an importing scratch leaf** (the dominant mode for
   the research-grade cores — fast iteration against cached `.olean`s, then verbatim port). A
   persistent **discipline framework** (`CLAUDE.md`: tactical, process, mathematical, and
   architectural lessons) is consulted and extended each session.
4. **Verification.** The trust anchor is `#print axioms`: a result is accepted only when its axiom
   footprint is `[propext, Classical.choice, Quot.sound]`. Green build ≠ certified; the axiom
   footprint is re-checked after every structural change.
5. **Auto-documentation.** A `codebase-outliner` agent regenerates the dependency-graph +
   math↔Lean correspondence outline (A3) from the current source.
6. **Blueprint.** Declarations are tagged with `@[blueprint]` (LeanArchitect); `lake build
   :blueprint` extracts a graph whose edges are read **from the actual Lean proof terms**;
   `leanblueprint` renders a human-auditable web + PDF blueprint (A5/A6) carrying, for each result,
   its statement, a proof sketch, a link to the formal Lean declaration, and a `leanok`
   formalization marker.

**This session's instance of the cycle** closed the final two leaves of the bridge
(`weakEvolution_test_C1c_On`, `transportedIntegral_hasDerivAt_zero` — the C¹_c test-class
enlargement and the diagonal chain rule), re-certified the axiom footprint, regenerated the
outline, and produced the blueprint with proofs — the commit trail in §6.

## 5. Reproducibility

**Toolchain (pinned).**
- Lean `leanprover/lean4:v4.29.1`
- Mathlib `v4.29.1` (`Vlasov/lakefile.toml`)
- Blueprint: `LeanArchitect` (`hanwenzhu/LeanArchitect`) + `leanblueprint` + `plasTeX` +
  `plastexdepgraph`; PDF via `xelatex`/`latexmk`; graph via `graphviz`.

**Build + certify the formalization.**
```bash
cd Vlasov
lake exe cache get        # fetch mathlib oleans
lake build                # builds the full library (0 sorry)
# axiom certification (must print [propext, Classical.choice, Quot.sound]):
echo '#print axioms Vlasov.weak_isLagrangianVlasovSolutionOn' | lake env lean --stdin
```

**Regenerate the outline (A3).** Run the `codebase-outliner` agent (writes
`formalize/codebase-outline.md`).

**Regenerate the blueprint (A4–A6).**
```bash
cd formalize/certification/blueprint-demo
lake build :blueprint                 # extract nodes + dependency graph from Lean
git init -q .                         # leanblueprint resolves the project root via git toplevel
leanblueprint web                     # → blueprint/web/  (run twice to settle refs)
leanblueprint pdf                     # → blueprint/print/print.pdf
```

## 7. Notes for the paper

- The **methodological contribution** is the reproducible agent-assisted pipeline (§3) with a
  *machine-checkable* acceptance criterion (the axiom footprint, §2) and *human-auditable*
  provenance (the auto-generated blueprint linking each informal proof sketch to its formal Lean
  term, A5).
- The **mathematical contribution** is the formal superposition principle for the Vlasov continuity
  equation (`weak_isLagrangianVlasovSolutionOn`), whose research-grade core is the *variational
  equation* — the C¹ dependence of an ODE flow on its initial point, **absent from Mathlib** and
  built in-house (`charFlow_hasFDerivAt_in_initialPoint`, via an explicit fundamental-matrix /
  Dyson-series construction). This lemma is a reusable, PR-able Mathlib asset.
- Honest scoping: the universal (all-time) form of the superposition principle is obtained by
  window-gluing and is left as a deferred follow-on; the per-window `_On` form is complete.
