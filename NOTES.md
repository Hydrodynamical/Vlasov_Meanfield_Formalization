## Three proofs that landed

### `empiricalMeasure_isProbabilityMeasure` ([Basic.lean:115](Vlasov/Vlasov/Basic.lean:115))

`μ^N(univ) = 1` for the empirical measure `(1/N) Σᵢ δ_{(Xᵢ,Vᵢ)}` when N ≥ 1.

```lean
omit [NeZero d] in
lemma empiricalMeasure_isProbabilityMeasure (N : ℕ) [NeZero N]
    (X V : Fin N → PhysSpace d) :
    IsProbabilityMeasure (empiricalMeasure N X V) := by
  refine ⟨?_⟩
  simp only [empiricalMeasure, Measure.smul_apply, Measure.finset_sum_apply,
             measure_univ, Finset.sum_const, Finset.card_univ, Fintype.card_fin,
             smul_eq_mul, nsmul_eq_mul, mul_one]
  exact ENNReal.div_mul_cancel
    (Nat.cast_ne_zero.mpr (NeZero.ne N)) (ENNReal.natCast_ne_top N)
```

Worked first attempt after grep-locating the four needed Mathlib lemmas
(`Measure.smul_apply`, `Measure.finset_sum_apply`, the
`Measure.dirac.isProbabilityMeasure` instance, `ENNReal.div_mul_cancel`).

### `gradient_zero_of_even` ([Basic.lean:99](Vlasov/Vlasov/Basic.lean:99))

For an even differentiable `W : ℝ^d → ℝ`, `gradient W 0 = 0`.

Proof structure: chain rule on `W ∘ Neg.neg = W` gives
`fderiv W 0 = -fderiv W 0`; push through `(InnerProductSpace.toDual).symm`
to get `gradient W 0 = -gradient W 0`; conclude via `add_neg_cancel` +
`(smul_eq_zero.mp …).resolve_left`.

Two non-obvious gotchas worth recording:

- `EuclideanSpace ℝ (Fin d) = WithLp 2 (Fin d → ℝ)` makes
  `HasFDerivAt.comp` misunify the base point — fix is to write
  `h_W_at_neg0 : HasFDerivAt W (fderiv ℝ W 0) (-(0 : PhysSpace d))`
  with an explicit `rw [neg_zero]` before invoking the chain rule.
- `simp` on the gradient unfolding hits `maxRecDepth`. Use explicit
  `congrArg (toDual …).symm h_fderiv |>.trans (map_neg _ _)` instead.

### `meanFieldLimit` ([Basic.lean:534](Vlasov/Vlasov/Basic.lean:534))

The mean-field limit corollary: `sup_{t ∈ [0,T]} W₁(μ_t^N, f_t) → 0` as
N → ∞, given `hInit` and the Dobrushin estimate `hDobrushin` as
hypotheses.

This is the only proof in the file that *cannot* run the .tex's actual
argument — it would need `weakEvolutionEmpiricalMeasure` and `dobrushin`
to be discharged first. Instead it's stated as a deduction from
`hDobrushin` (treating Dobrushin's conclusion as a hypothesis), which
makes it an honest squeeze argument: `0 ≤ sup_t W₁ ≤ exp(C·T)·W₁(μ_0^N, f₀) → 0`.

**This proof was a true human-agent collaboration.** The sorry-prover
agent produced the full skeleton on its own — `hsup_bound` (the substantive
piece, using `iSup_le` twice and the calc chain through `hDobrushin`) and
the `hUpper` strategy — and ran out of iterations at exactly the final
API call. Its attempt log named the precise fix needed:
`Or.inr ENNReal.ofReal_ne_top` for the `ENNReal.Tendsto.const_mul`
disjunctive condition. Pasting in the skeleton + applying the agent's
own hint + replacing one phantom lemma (`Real.exp_le_exp_of_le` →
`Real.exp_le_exp.mpr`) closed it.

Attempt log: [`formalize/logs/prover-cycle-1.md`](formalize/logs/prover-cycle-1.md)
(second attempt section).

## Translator bugs surfaced (and fixed)

The translator agent produces statement-only skeletons. Twice it
introduced subtly malformed statements that the prover later caught.
Both were instances of *missing constraints between free parameters*.

### Bug 1: `weakEvolutionEmpiricalMeasure` had a free `R_N`

Original (broken) shape:

```lean
theorem weakEvolutionEmpiricalMeasure ... (R_N : ℝ → ℝ) (t : ℝ) :
    HasDerivAt (...) (... + R_N t) t  ∧  |R_N t| ≤ bound
```

`HasDerivAt` has a *unique* derivative, so the first conjunct
constrains `R_N t` to a specific real number. The ∀-statement over
`R_N` is then false (it holds for at most one `R_N`).

Prover diagnosed this on the very first `--prove-next` attempt
(see [`formalize/logs/prover-cycle-1.md`](formalize/logs/prover-cycle-1.md),
first attempt). Fix: existential. Now [Basic.lean:185](Vlasov/Vlasov/Basic.lean:185):

```lean
∃ r : ℝ, HasDerivAt (...) (... + r) t  ∧  |r| ≤ bound
```

### Bug 2: `meanFieldLimit` had a disconnected `X₀ V₀`

Original (broken) shape:

```lean
(X₀ V₀ : (N : ℕ) → Fin N → PhysSpace d)         -- initial data
(X V   : (N : ℕ) → ℝ → Fin N → PhysSpace d)     -- trajectories
(hSol  : ∀ N, IsNewtonSolution N gradW (X N) (V N))
(hInit : Tendsto (fun N => W₁(empiricalMeasure (X₀ N) (V₀ N), f₀)) atTop (𝓝 0))
```

`X₀` is never linked to `X N 0` (or vice versa). `hInit` is about
`X₀`; the Dobrushin bound is about `X N 0`. Nothing connects them.

Prover diagnosed this in its second cycle. Fix: drop `X₀ V₀` parameters
entirely; phrase `hInit` directly in terms of `X N 0`, `V N 0`. The
.tex's `(X_0^N, V_0^N)` notation IS by definition the trajectory's
initial value. Now [Basic.lean:544–552](Vlasov/Vlasov/Basic.lean:544).

**Lesson**: the LaTeX→Lean translator (a single-pass agent that produces
statements without proving anything) systematically introduces this kind
of bug — it instantiates each `\X`, `\V`, `R_N`, `(X_0^N, V_0^N)` etc.
as an independent free parameter, missing the *implicit constraints*
that the original prose conveys with quantifier scope or "where" clauses.
A future improvement would be a translator post-pass that re-reads each
theorem looking for free parameters with no constraining hypotheses and
flags them.

## Harness lessons (the agent system itself)

The pipeline went through several iterations of debugging. Recording
the failure modes because they generalize.

### Translator: `import Mathlib` and `import Mathlib` only

Letting the translator emit `import Mathlib` (not specific modules) was
the right call. The fixer's job becomes "patch type errors" not "guess
which imports are needed." Compile time is ~75 s once cached; not
worth optimising at the cost of agent complexity.

### Fixer: works well as a bounded loop with revert

The fixer landed the full skeleton in 3 of its 12-iteration budget
(see [`formalize/logs/03-fixer.log`](formalize/logs/03-fixer.log)).
Substantive fixes it made on its own:
- `ℝ≥0` / `ℝ≥0∞` → `NNReal` / `ENNReal` for parser disambiguation
- `fderiv` → `gradient` to match inner-product calculations
- Explicit `@inner ℝ (PhysSpace d) _` ascriptions to disambiguate dot products
- Replaced bare `Continuous f` with narrow-convergence formulation in
  `vlasovWellPosedness`

### Prover: needs `--effort low` to break the silent-thinking trap

**Most important harness lesson.** The default extended-thinking budget
let the prover deliberate for ~40 minutes without making a single tool
call (no `lake build`, no `Read`, no `Edit`). The §4 small-edit
discipline in the agent spec was supposed to fix this; it didn't,
because the discipline only applies *once edits start*.

Adding `--effort low` to the prover's `claude -p` invocation
([`formalize.sh:124`](formalize.sh:124)) flipped the behavior: 0 bytes
of log → 763 bytes, 0 iterations → 8 iterations of real edits + builds.
The trade-off (less per-tactic thinking, more total iterations) is
exactly right for an iterative tool-use loop.

### Driver: timeout watchdog needs three coordinated pieces

macOS lacks GNU `timeout`. Used `perl -e 'alarm shift; exec @ARGV'`
([`formalize.sh:120`](formalize.sh:120)) — alarm survives exec, target
process dies on SIGALRM with rc=142. The harness needs three
non-obvious bits to compose correctly:

1. `{ pipe; } || rc=$?` — captures SIGALRM=142 across `set -euo
   pipefail`. Plain `|| true` zeroes PIPESTATUS and loses the signal.
2. Auto-restore from `<file>.prover-bak` after the prover stage if the
   checkpoint still exists ([`formalize.sh:251`](formalize.sh:251)).
   Killed-mid-edit prover never reaches its own revert step.
3. `${effort_args[@]+"${effort_args[@]}"}` for the optional `--effort`
   argument. Bash 3.2 on macOS treats `${arr[@]}` as unbound under
   `set -u` even when explicitly initialised as `local -a arr=()`.

### Selection mode: `--prove-easiest` is the better default

`--prove-next` (target the verifier's top recommendation) kept selecting
`weakEvolutionEmpiricalMeasure`, which is the hardest sorry in the file
and consistently timed out the prover. `--prove-easiest` (score all
sorries on a five-criterion rubric: size, conclusion shape, dependency
on other sorries, verifier hints, concreteness) picked `meanFieldLimit`
instead, which the agent actually came close to proving.

If running fresh, default to `--prove-easiest`. Use `--prove-next` only
when you specifically want the report's curated priority order.
