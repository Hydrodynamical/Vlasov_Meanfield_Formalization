## Architectural shift: sidecar plan-file IPC

The biggest change is structural, not feature-shaped.

**Before this session**: the decomposer's only "output" was Lean code
(helper lemmas + a combinator in the parent's body) plus a free-form
markdown attempt log. Any downstream consumer (sorry-prover scoring a
helper, lean-verifier producing a report) had to *re-parse* the Lean
file's comments and inline structure to understand what was a planned
helper vs. an incidental sorry.

**After this session**: the decomposer additionally emits a typed
**JSON sidecar** at `formalize/plans/<targetName>.json`. Schema v1:

```json
{
  "schema_version": 1,
  "parent": { "name": "...", "kind": "theorem", "tex_label": "...",
              "file": "...", "line": ... },
  "helpers": [
    { "name": "...", "line": ..., "difficulty": 1-5, "deps": [...],
      "mathlib_hints": [...], "one_line_math": "..." },
    ...
  ],
  "residual_glue": {           // nullable
    "line": ..., "composition": [...], "strategy": "...",
    "tactic_sketch": "..."     // machine-executable tactic block
  }
}
```

Key design properties:

- **No `status` field**. Helper status (proved / sorry) is computed at
  read time by the verifier from current build warnings. Storing
  status would create staleness; this way a plan is the static
  dependency graph and status is always fresh.
- **The in-file artefact is a 2-line pointer**, not the full plan.
  Lean source stays focused on Lean content; reasoning lives in the
  sidecar. Reformats of `Basic.lean` don't decouple the plan from the
  sorries it annotates.
- **The sidecar's `tactic_sketch` is machine-executable** (unlike the
  blocklist-restricted in-file combinator). This lets the prover's
  residual-glue fast path try the sketch verbatim before falling into
  iteration — a real speedup, not "do one iteration then fall back to
  iteration".
- **Difficulty 1–5 is a v1 limitation**: it conflates length with
  novelty. A long-but-mechanical proof and a short-but-conceptual one
  can both score 5 today. The schema's `schema_version` lets v2 split
  into `length_estimate` + `novelty` if it becomes worth it.

## Agent ownership: scaffold vs. branch-closing

The decomposer's contract was tightened: **the decomposer writes
structure; the prover closes branches**. In the parent theorem's body
the decomposer may use only `refine`, `intro`, `obtain`, `case`, `·`,
and `sorry` leaves. It may NOT use `exact`, `rfl`, `simp`,
`simp_rw`, `decide`, `ring`, `linarith`, `norm_num`, `omega`, `aesop`,
or any other proof-closing tactic.

Enforcement is via the **sorry-count invariant** (parent body must
contain ≥ 1 `sorry` after decomposition), not a grep-blocklist on the
forbidden tactics. The blocklist has too many false positives
(`Iff.rfl`, `simp_rw`, lemma names containing `exact`) to be a hard
revert trigger; the sorry-count check captures the real intent
("decomposer must leave work for the prover") more robustly.

**Scope**: this contract applies to combinators the decomposer NEWLY
writes. Existing combinators that predate the contract — notably
`weakEvolutionEmpiricalMeasure`'s `exact diagonalCorrection_bound`
branch closure at [Basic.lean:420](Vlasov/Vlasov/Basic.lean:420) — are
**grandfathered**: we do not revert real proof work to satisfy a new
spec.

## Streaming visibility

The `delegate()` helper in `formalize.sh` previously ran each agent
via `claude -p` and tee'd the output. The problem: `claude -p` in
default mode buffers the entire session until the assistant produces
a final message — so SIGALRM-killed runs left **0-byte logs**, and we
had no way to distinguish "agent was thinking silently" from "agent
was busily editing with output buffered."

Fix: switch to `--output-format stream-json --verbose` and pipe
through `jq -rR --unbuffered '<filter>'` to render per-event JSONL
into a human-readable trace. Two sibling files per agent call now:

- `<log>.jsonl` — raw archive (every Read/Edit/Bash event, full
  fidelity, for forensics)
- `<log>` — rendered trace (`[Read] ...`, `[Bash] ...`, `[Edit] ...`,
  `[result] success duration=...ms cost=$...`)

This caught a real failure mode early in the session: the
sorry-decomposer's first end-to-end run (`--decompose
weakEvolutionEmpiricalMeasure`) timed out at 900s after producing
*only* the §3 plan-write and §4.0 baseline build. The streaming
trace let us reconstruct the wall-clock breakdown and propose two
surgical spec changes (skip §4.0 baseline; inline plan via single
`Edit` instead of separate-log heredoc) that fit the next run in
budget.

## Concrete proof landed: `empiricalMeasure_integral_eq`

Plan-aware `sorry-prover` cycle on `--prove-easiest`:

1. Globbed `formalize/plans/*.json`, parsed the one sidecar, built a
   lookup map.
2. Scored candidates: helper 1 (`empiricalMeasure_integral_eq`,
   difficulty 1, leaf) → score 5, beating all other helpers and the
   non-decomposed sorries.
3. Loaded the plan's `mathlib_hints` for this helper as context.
4. Closed in 3/8 iterations:
   ```lean
   lemma empiricalMeasure_integral_eq (N : ℕ) [NeZero N]
       (X V : Fin N → PhysSpace d) (φ : PhaseSpace d → ℝ) :
       ∫ z, φ z ∂(empiricalMeasure N X V) =
         (1 / (N : ℝ)) * ∑ i : Fin N, φ (X i, V i) := by
     simp only [empiricalMeasure]
     rw [integral_smul_measure]
     rw [integral_finset_sum_measure (fun i _ => integrable_dirac (by simp))]
     simp [integral_dirac, ENNReal.toReal_div, ENNReal.toReal_natCast, smul_eq_mul]
   ```
   Each of `integral_smul_measure`, `integral_finset_sum_measure`,
   `integral_dirac` came from the sidecar JSON's `mathlib_hints`
   array — no LLM re-derivation of the API to use.

After the run, the verifier auto-flipped helper 1's status to
**proved** in the regenerated `report.md` without any plan-file edit.
The recommended-next-steps section now annotates helper 1 with
"already proved" and demotes it.

Cost for this cycle: $0.54 (pre-verifier) + $0.91 (prover) + $0.56
(post-verifier) ≈ **$2.01 for one helper landed**.

## Lessons (small but transferable)

1. **`--effort low` is not always the right knob for agents.** It
   helped the prover (where the failure mode was "extended thinking,
   no tool calls") but would have hurt the decomposer (where the
   bottleneck was thinking-quality on planning). Pass effort
   per-agent in `delegate()`, not globally.

2. **macOS bash 3.2 has no GNU `timeout`.** The perl idiom `perl -e
   'alarm shift; exec @ARGV' SECONDS CMD ARGS...` works because the
   alarm timer survives the `exec` and SIGALRM kills the target
   process. Standard portability trick worth remembering.

3. **Pipefail + nested pipes is fiddly.** `{ pipe; } || rc=$?`
   captures the pipeline's exit code across `set -euo pipefail`;
   plain `|| true` zeroes PIPESTATUS and loses the SIGALRM=142
   signal. The brace-group form preserves it.

4. **Empty bash arrays trip `set -u` on macOS bash 3.2.** Use
   `${arr[@]+"${arr[@]}"}` to expand-or-empty safely; the bare
   `${arr[@]}` will trigger "unbound variable" even if `local -a
   arr=()` explicitly initialised it.

5. **Inline metadata in source files is an anti-pattern for
   agent-to-agent IPC.** Comments are for humans; structured
   artefacts (JSON, TOML, whatever) are for agents. Lean source
   files reformat; sidecar files don't decouple from their anchors
   the same way.

6. **Scaffold-only contracts need a sorry-count invariant, not a
   tactic blocklist.** `exact`, `rfl`, `simp` appear in lemma names
   (`Iff.rfl`, `Eq.refl`, `simp_rw`) and as substrings of allowed
   tactics — grep enforcement has false positives. The real
   invariant is "decomposer must leave at least one `sorry` for the
   prover to discharge"; check that directly.

7. **Difficulty scales conflate length and novelty.** 1–5 was fine
   for v1 but won't scale; reserve `schema_version` so v2 can split.
